# 문서 가이드 (Documentation Rules)

> "문서만으로 개발 가능"을 유지하기 위한 문서 품질 규칙. 코드 규범은
> `docs/coding-guide.md`, 프로세스는 `docs/methodology.md`.

## 1. 문서 3층 역할 (어디에 무엇을 쓰나)

| 층 | 문서 | 담는 것 | 안 담는 것 |
|---|---|---|---|
| 결정 | `AGENTS.md` | 결정·원칙·정책·why | 모듈 구현 상세 |
| 시스템 | `docs/architecture.md` | 컴포넌트가 맞물리는 방식·데이터흐름·상태·배포 | 결정 근거, 계약 상세 |
| 모듈 | `docs/spec/*.md` | 모듈 입출력 계약·불변식·테스트케이스 | 시스템 전체 뷰 |

**한 사실은 한 곳에만(Single Source).** 다른 문서에선 링크로 참조하고
복사하지 않는다. 요약이 필요하면 "요지 + 링크" 형태로.

## 2. 드리프트 방지 (변경 시 무엇을 함께 고치나)

- **결정이 바뀌면 `AGENTS.md`를 먼저 고친다**(진실의 출발점). 그다음 영향받는
  architecture/spec을 맞춘다.
- 스키마가 바뀌면 `spec/data-model.md` → 이를 참조하는 spec들 → 코드 순.
- 결제 모델·패턴이 바뀌면 `AGENTS.md §2.5` → `payment-flows.md` →
  `spec/executor.md`.
- PR 리뷰 시 "코드는 바뀌었는데 스펙/문서가 안 바뀐 곳"이 없는지 확인.

## 3. 스펙 작성 규칙

- 5섹션 고정: 목적 / 계약 / 불변식 / 수용기준 / 테스트케이스
  (`spec/README.md`).
- 계약 타입은 `shared` Zod를 참조(중복 정의 금지).
- 테스트 케이스는 표로, 픽스처를 명시해 그대로 코드로 옮길 수 있게.
- 불변식에는 보안·격리 관련 "항상 참"을 반드시 포함(예: 비밀 미노출).

## 4. 다이어그램 규칙

- ASCII 다이어그램 우선(diff·리뷰 용이). **신뢰 경계(Trusted/Untrusted)를
  항상 표기**. 데이터 흐름은 화살표 방향과 무엇이 흐르는지 라벨.
- 그림이 텍스트보다 명확할 때만 넣는다(장식용 금지).

## 5. 언어 / 스타일

- 서술은 한국어(현 문서 관행). **코드·타입·식별자·파일명은 영어.**
- 결정에는 근거(why)를 함께. "무엇"만 적고 "왜"를 빠뜨리지 않는다.
- 상대 날짜 금지 — 절대 날짜로("2026-09-02"). 확정일·변경일 표기.
- 단정과 추정을 구분(조사 결과엔 확신도·출처, 예: `payment-flows.md`).

## 6. 용어집 (Glossary) — 문서·코드 공통

| 용어 | 뜻 |
|---|---|
| 브로커(Broker) | 신뢰 영역. 정책·실행·감사·통지를 담당하는 익스텐션 코어 |
| 두뇌(Agent/Brain) | Untrusted. 무엇을 할지 결정하는 LLM 루프 |
| 손(Hands) | content script의 DOM 조작(navigate/read/click/fill) |
| 신뢰 경계 | Untrusted↔Trusted 경계. 모든 교차 메시지는 Zod 검증 |
| 패턴 B | 화면 클릭 + 폰 승인(카카오·토스). 외부 인간 게이트=폰 생체 |
| 패턴 C | 사전 승인 무마찰(쿠팡 원터치). 외부 게이트 없음 → 정책+확인+통지 |
| 패턴 A | 빌링키/정기결제(후순위). 최초 1회 인증 후 서버-투-서버 |
| out-of-band | 브라우저 밖 채널(폰 앱)에서 일어나는 최종 승인 |
| refstore | 빌링키 참조·PII의 암호화 저장소(원시 카드번호 저장 안 함) |
| verifiedAmount | executor가 결제창에서 독립 파싱한 실제 금액(위조 방지 기준) |
| BrokerTools | 두뇌가 코어에 접근하는 유일한 도구 인터페이스(경계) |
| decision | 정책 판정 결과: allow / confirm / deny |
| 감시(Watch) | 지정가 모니터링 → 조건 충족 시 결제 트리거(플래그십, `spec/watch.md`) |
| confirm 해소 | UI [승인]/[거절] 또는 타임아웃으로 pending confirm을 재개/취소(`resolveConfirmation`) |

## 7. 문서 리뷰 체크리스트

- [ ] 새 사실이 올바른 층(결정/시스템/모듈)에 있고 중복이 없다
- [ ] 변경으로 드리프트된 다른 문서가 없다(§2)
- [ ] 용어가 용어집과 일치한다
- [ ] 결정에 why가 있고, 조사엔 확신도·출처가 있다
- [ ] 비밀/PII 예시가 더미값이다
- [ ] 신뢰 경계·보안 불변식이 스펙에 명시돼 있다
