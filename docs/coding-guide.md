# 코딩 가이드 (Coding Conventions)

> 프로세스는 `docs/methodology.md`, 이 문서는 **코드를 어떻게 쓰는가**.
> 사람·코딩 에이전트 공통 규범. 위반은 리뷰에서 반려.

## 1. TypeScript

- `strict: true` 고정. `any` 금지 — 불가피하면 `unknown` + 좁히기.
- 비-null 단언(`!`) 남용 금지. 옵셔널은 명시적으로 다룬다.
- **판별 유니온은 exhaustive 처리**. `switch`에 `default: assertNever(x)`로
  누락을 컴파일 타임에 잡는다.
- **타입은 `shared`의 Zod에서 추론(`z.infer`)해 재사용.** 같은 개념의 타입을
  중복 정의하지 않는다(SDK/`shared` 타입 우선).
- 공개 함수는 반환 타입을 명시.

## 2. 구조 / 네이밍

- 한 모듈 = 한 책임. 로직(순수)과 부수효과(IO)를 파일로 분리.
- **정책·판정 로직은 순수 함수**로. 시계·스토리지·랜덤은 인자로 주입
  (테스트 가능성, `spec/policy.md`).
- 파일명 kebab-case, 타입/컴포넌트 PascalCase, 변수/함수 camelCase, 상수
  UPPER_SNAKE. 도메인 용어는 `docs/documentation-guide.md` 용어집을 따른다.

## 3. 신뢰 경계 / 검증

- **경계를 넘는 모든 입력은 `shared` Zod로 `safeParse`.** 실패 = 즉시 거절,
  신뢰 영역 진입 금지 (`AGENTS.md §2.6`).
- 에이전트(두뇌)는 `BrokerTools` 인터페이스 밖으로 코어에 접근하는 코드를
  만들지 않는다 (`spec/agent-integration.md`).
- **불확실하면 닫는다(fail closed)**: 판정·검증이 애매하면 deny/거절이 기본.

## 4. 보안 코딩 (필수 — 조직 규칙 반영)

- **하드코딩 금지**: API 키·토큰·봇 토큰·빌링키·접속정보를 코드/커밋에 넣지
  않는다. `.env`는 커밋 제외, `.env.example`에 더미값만.
- **결제 비밀 미취급**: 카드번호·CVV·결제 비밀번호·로그인 자격증명을 저장·
  입력·전송하는 코드를 작성하지 않는다(범위 밖, `AGENTS.md §1.1`). 관련 UI가
  결제 흐름에 나타나면 진행 중단(`spec/executor.md`).
- **PII 로그 금지**: 휴대폰번호·생년월일 등은 로그·에러 메시지·감사 레코드에
  원문으로 남기지 않는다. 저장 시 WebCrypto 암호화(`refstore`).
- **금지 기법**: 보안 키패드 우회, 합성 클릭 키패드 입력, FDS/안티봇 회피,
  쿠팡 6자리 비번 경로. 필요해 보이면 코드 대신 설계 재검토 요청(`§2.5`).
- **최소 권한**: manifest 권한은 필요한 것만. `debugger` 권한 미사용
  (`spec/agent-integration.md` 방식 A 유지). 결제사/쇼핑몰 host 권한은 명시적.
- 에러 메시지·예외에 비밀/PII가 섞이지 않도록 정제(redact) 후 노출.

## 5. 에러 처리

- 타입드 에러 사용, 뭉뚱그린 `catch(e){}`로 삼키지 않는다.
- 재시도 가능(네트워크/일시)과 불가능(검증 실패)을 구분해 처리.
- 결제 실행 경로의 예외는 안전한 상태(미결제)로 수렴하고 audit에 기록.

## 6. 테스트

- 정책 엔진 커버리지 100% 목표(순수 함수). 스펙의 테스트 케이스 표를 그대로
  옮긴다(`spec/policy.md`).
- 결정적 테스트: 시계·사용량·랜덤을 주입해 고정. 시간 의존 로직은 경계값
  (자정/월말) 포함.
- **실제 카드·계정 금지.** 더미 프로필 + 테스트 쇼핑몰/모킹 결제창만.
- 테스트명은 동작을 서술("denies over per-transaction limit").
- **모킹 결제창/픽스처 전략**: E2E는 실제 카카오·쿠팡 창 대신 **고정 HTML
  픽스처**(결제창·완료 페이지 스냅샷)를 로컬 서버로 서빙해 Playwright가 로드한다.
  각 어댑터(`SimplePayAdapter`)는 파싱 대상 셀렉터/완료 신호를 픽스처로 검증하고,
  실결제 캡처(payment-flows 검증 항목)로 픽스처를 갱신한다. `verify()`·완료 파싱은
  픽스처 단위 테스트, 폰 승인 단계는 스텁으로 대체.

## 7. 로깅

- 구조적 로그, 레벨 구분. **비밀/PII 절대 금지**(§4).
- 결제 시도는 audit에 기록(요청자·금액·머천트·판정·결과·시각). 원문 비밀 없음.

## 8. 커밋 / PR / 의존성

- Conventional Commits(`feat/fix/docs/test/refactor`). 작은 PR.
- PR은 관련 `spec/<module>.md`를 링크하고 DoD 체크리스트 첨부
  (`methodology.md §4`).
- 의존성은 버전 핀(`stack.md`). 새 의존성 추가는 PR에서 사유 명시.
